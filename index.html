🗄️ Section 1

Data Foundation & Synthetic Data

A governed, layered data estate with synthetic data that enables safe testing without exposing production PII.

Bronze
Raw Ingest
Synthetic CSVs pushed to a Databricks Volume via SONIC_ingest_all_tables.py. Records land as-is.
Silver
Cleansed & Dedup-Ready
Standardised customer records, duplicate candidates, deactivation & reactivation staging tables.
Gold
Operational & Reporting
Resolved customer master — consumed by downstream analytics and validated by the Test Factory.
📦

Synthetic / SONIC-Style Data

  • Mirrors production record structures (IDs, name variants, address permutations, edge-case duplicates) — no real PII
  • Pushed to a Volume under the governed UC catalog path (e.g. huron_singapore_dma_…)
  • Covers all 9 dedup categories: WB, CB, EX, FZ, AD, MS, TB, FP/FN, OP
✅

Why It Matters

  • Repeatable demos — same inputs, predictable outputs every run
  • Safe testing — engineers test fuzzy-match thresholds against known ground-truth labels
  • Closed loop — each synthetic record class maps directly to a Test Factory scenario

The 6-Step Factory Loop

1

Environment Discovery

Databricks MCP enumerates live catalogs, schemas, tables, warehouses — no hardcoded paths.

2

Rule Extraction

Agent reads dedup rules from docs/notebooks and maps each to a scenario category (WB, CB, EX, FZ, AD, MS, TB, FP, FN, OP).

3

Scenario & Workbook Alignment

Markdown scenarios aligned to Excel package; Python sync scripts seed workbooks from repo content.

4

Validation Script Execution

4 PySpark/SQL scripts run against live silver tables via REST 2.1: duplicate_log_rules, threshold_boundaries, false_positive_negative, operational_pipeline.

5

Results & Post-Run Sync

PASS/FAIL written to markdown tracker and Excel workbooks (03_Execution_Results, 04_Traceability) via sync_test_factory_post_run.py.

6

Automatic Jira Defect

On FAIL, Jira MCP creates a Bug in DP / DP-4 with auto labels. Jira key written back to execution tracker — no manual copy-paste.
